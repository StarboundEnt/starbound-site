# Accessibility statement

Starbound aims for this demo to meet **WCAG 2.2 Level AA**. This is a target, not a conformance claim: the prototype has not yet completed an independent accessibility audit.

## Measures currently included

- Semantic headings, landmarks, fieldsets, labels, buttons, and lists.
- A skip link to the main demo.
- Visible keyboard focus styles.
- Native controls for keyboard and assistive-technology compatibility.
- Live regions for profile changes and AI status messages.
- Responsive layouts that do not require a fixed screen orientation.
- Reduced-motion support through `prefers-reduced-motion`.
- Text labels in addition to colour and decorative icons.
- Permanent emergency and crisis-support information.

## Target testing

Before making a WCAG conformance claim, test the complete public page at desktop and mobile breakpoints for:

- Keyboard-only navigation and focus order.
- Focus visibility and focus not being obscured.
- Screen-reader names, roles, states, and status announcements.
- Text and non-text contrast.
- Reflow at 320 CSS pixels and zoom to 200% and 400%.
- Touch target size and spacing.
- High-contrast and forced-colour modes.
- Reduced motion.
- Plain-language comprehension with young people and people with varied digital literacy.
- Behaviour when web fonts, images, JavaScript, or the AI endpoint fail.

## Known gaps

- No independent WCAG 2.2 AA audit has been completed.
- The generated AI copy can vary in readability and complexity.
- The constellation is decorative and does not provide additional information beyond the adjacent text.
- Real-device and assistive-technology coverage has not yet been documented.

Accessibility feedback should identify the page, browser/device, assistive technology if applicable, and the task that was difficult. A public contact method must be added before launch.
